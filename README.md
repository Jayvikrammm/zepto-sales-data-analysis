# Zepto Sales Data Analysis

A data analyst portfolio project exploring product pricing, stock availability, discounts, and category-level revenue using real-world grocery delivery data from **Zepto** (via the `zepto_v2.csv` dataset). The entire analysis — from data cleaning to feature engineering to aggregation — was performed using **Python, pandas, and NumPy**.

---

## 📌 Project Overview

This project analyzes Zepto's product catalog to answer practical business questions such as:

- Which products are the most expensive, and which are out of stock?
- How do discounts vary across price points and categories?
- What is the estimated revenue generated by each product category?
- How does price scale with product weight (price per gram)?
- How can products be segmented into meaningful weight tiers for easier comparison?

The goal was to practice real-world data cleaning, exploratory data analysis (EDA), and translating the same business logic across both **pandas** and **SQL**.

---

## 🗂 Dataset

**File:** `zepto_v2.csv`

Key columns used in this analysis:

| Column | Description |
|---|---|
| `name` | Product name |
| `category` | Product category (e.g. Beverages, Snacks, Dairy) |
| `mrp` | Maximum retail price |
| `discountedSellingPrice` | Actual selling price after discount |
| `discountPercent` | Discount applied, as a percentage |
| `availableQuantity` | Units currently available in stock |
| `weightInGms` | Product weight in grams |
| `outOfStock` | Boolean flag indicating stock availability |

> **Note:** The raw CSV required specifying `encoding='cp1252'` when loading with pandas, as it contains Windows-1252 encoded characters (e.g. smart quotes) that raise `UnicodeDecodeError` under the default UTF-8 encoding.

## 🔍 Key Analysis Steps

### 1. Data Cleaning
- Fixed CSV encoding issues (`cp1252`)
- Converted price fields from paise to rupees where applicable
- Handled missing values before type conversions (e.g. `astype(int)`)

### 2. Stock & Price Filtering
- Filtered in-stock vs. out-of-stock products
- Identified the top N highest/lowest priced products using `nlargest()` / `nsmallest()`
- Applied multi-condition filters (e.g. `mrp > 500` and `discountPercent < 10`) using both boolean indexing and `.query()`

### 3. Category-Level Revenue
- Calculated estimated revenue per category by multiplying discounted selling price by available quantity, then aggregating with `groupby()`:
  ```python
  df['revenue'] = df['discountedSellingPrice'] * df['availableQuantity']
  category_revenue = df.groupby('category')['revenue'].sum().sort_values(ascending=False)
  ```

### 4. Discount Analysis
- Computed average discount percentage by category using `.groupby().mean()`
- Compared discount depth against price tiers

### 5. Price-per-Gram & Weight Tiers
- Engineered a `price_per_gram` metric to compare value across differently sized packs:
  ```python
  df['price_per_gram'] = df['discountedSellingPrice'] / df['weightInGms']
  ```
- Segmented products into weight tiers (`Low`, `Medium`, `Bulk`) using `np.select()` with range-based conditions

### 6. Deduplication
- Used `drop_duplicates(subset='name')` to remove repeated product listings before analysis, ensuring counts and rankings reflected distinct products

## 📊 Sample Findings

- Certain categories (e.g. *Home & Cleaning*, *Health & Hygiene*) generate disproportionately high estimated revenue relative to catalog size.
- A meaningful share of higher-MRP products (>₹500) carry relatively shallow discounts (<10%), suggesting discount strategy varies by price tier rather than being applied uniformly.
- Price-per-gram analysis reveals that larger pack sizes don't always translate to better per-unit value — some smaller packs are more cost-efficient.
